# github-vm — MacRDP

## الحالة

سير عمل `MacRDP` اليدوي موجود في `.github/workflows/macrdp.yml`، لكنه يتوقف عمداً في فحص أمان قبل إنشاء حساب أو كلمة مرور أو نفق Ngrok. لا يسجل حالة `ONLINE`، ولا يستخدم `NGROK_AUTH_TOKEN`، ولا يفتح منفذاً عاماً. هذا الإيقاف مقصود، وليس نجاحاً في الاتصال.

## ما كان يفعله التنفيذ القديم

- `mac/start.sh` كان ينزّل `mac/login.sh` وقت التشغيل من مستودع خارجي متغير بدلاً من استخدام نسخة محلية مراجعة.
- كان ينشئ حساب `runneradmin` يدوياً بمعرّف UID ثابت `1001`، ويضع مجلد المنزل على `/Users/tcv`، ثم يضيف الحساب إلى مجموعة المديرين.
- كان يضبط كلمة مرور macOS ثابتة ومدمجة في السكربت، ويمنح Remote Management الوصول إلى جميع المستخدمين وجميع الصلاحيات.
- كان يفعّل مصادقة VNC القديمة ويكتب إعداداً مشتقاً من كلمة مرور ثابتة إلى ملف تفضيلات VNC. وكان `login.sh` يطبع كلمة المرور صراحةً.
- كان يمرر رمز Ngrok إلى أمر سطر أوامر، ويستخدم خيار المنطقة القديم `--region=in`، ثم يبدأ النفق في الخلفية من دون فحص استمرارية موثوق.
- كان سير العمل القديم ينزّل `start.sh` عن بُعد ولا يحدد مهلة للمهمة، ويشغّل `mxschmitt/action-tmate@v2` رغم أن الهدف سطح مكتب رسومي.

وقد عُطّل ملف سير العمل القديم `.github/workflows/main.yml.disabled` كي لا يستمر بتشغيل هذا المسار.

## سبب الإيقاف

تذكر Apple أن أداة `kickstart` لا تستطيع تمكين Screen Sharing على macOS 12.1 أو أحدث، وأن Screen Sharing المفعّل عبر `kickstart` يكون للعرض فقط على macOS 10.14 أو أحدث. لذلك لا يمكن اعتبار `macos-latest` مهيأً للتحكم التفاعلي الكامل بمجرد نجاح أوامر `kickstart` أو فتح المنفذ 5900. راجع [توثيق Apple لتمكين Remote Management](https://support.apple.com/ro-md/guide/remote-desktop/apd8b1c65bd/mac).

وتحذر Apple من أن بعض برامج VNC الخارجية لا تشفر ضغطات المفاتيح المرسلة عبر الشبكة. أما النفق الخام TCP إلى خادم VNC عام فلا يثبت وحده وجود تشفير طرف إلى طرف بين الهاتف والخادم. لذلك لا ينشئ هذا المستودع نفق VNC عاماً قبل اعتماد وسيلة نقل ومصادقة مدعومتين واختبارهما فعلياً. راجع [تحذير Apple بشأن وصول VNC](https://support.apple.com/guide/remote-desktop/virtual-network-computing-access-and-control-apde0dd523e/mac).

كما أن التنفيذ القديم كان يقتطع كلمة مرور VNC إلى أول 8 أحرف. أزيل هذا السلوك؛ لا توجد كلمة مرور ثابتة أو افتراضية جديدة، ولا يُطلب منك توفير Secrets إضافية.

حتى حساب Ngrok المجاني يتطلب إضافة بطاقة ائتمان أو خصم صالحة لاستخدام TCP endpoints؛ تذكر Ngrok أن البطاقة لا تُخصم. لا يطلب هذا المستودع منك شراء اشتراك أو إدخال بيانات بطاقة. راجع [قيود الخطة المجانية لدى Ngrok](https://ngrok.com/docs/using-ngrok-with/minecraft).

## Secrets والمتطلبات

لا يقرأ سير العمل الحالي أي Secret، بما فيه `NGROK_AUTH_TOKEN`، لأن إنشاء النفق في الظروف الحالية لا يحقق المتطلبات الأمنية والتحققية. لا تحتاج إلى إضافة `MACOS_USER_PASSWORD` أو `VNC_PASSWORD` أو `TAILSCALE_AUTHKEY` أو أي Secret آخر. ولا توجد مدخلات `workflow_dispatch` لكلمات المرور، ولا تُطبع كلمات مرور في Logs.

## التشغيل والتحقق

من GitHub افتح **Actions → MacRDP → Run workflow**. سيتوقف الفحص برسالة `MacRDP BLOCKED` قبل إنشاء أي خدمة عامة. هذه نتيجة فشل آمن وليست جلسة macOS متاحة. لا توجد بيانات اتصال أو مدة جلسة لأن النفق لا يبدأ.

لا يمكن تقديم تعليمات اتصال Android صالحة حتى يتوفر مُشغّل macOS يستطيع تمكين مشاركة الشاشة والتحكم بها بطريقة تدعمها Apple، مع قناة نقل مشفرة ومصادقة يمكن اختبارها دون كشف بيانات الاعتماد. لم يتم الادعاء بنجاح الاتصال.

## ما لم يتغير

ملف `win2022.txt` خارج مسار MacRDP ولم يُعدّل. وهو ملف نصي وليس سير عمل GitHub Actions نشطاً بامتداد YAML؛ يحتوي حالياً إعداد Windows مستقلاً وكلمة مرور ثابتة. راجعه أو احذفه بقرار منفصل إن كان لا ينبغي الاحتفاظ به.
